# l1_ring (option C, 3 Oct 2026): L1 adaptive augmentation of the ring position loop

Wesley, 3 Oct: "Lets try C in simulation" (adaptive control on the ring, after option A, the
disturbance estimate, removed the wind error in Gazebo: R0864 17.9 cm -> R0867 3.9 cm).

## 1. Question

Can an L1 adaptive augmentation hold the ring on its reference against both external forces (wind, a
push, an added mass) and internal model errors (the twin's +4.8 cm hold with z_ki 0, a thrust-map
error), which option A cannot see?

## 2. Hypothesis

**Where it acts.** Not on forces inside the planner: an adaptive force driven by the plan's own
cable force cannot match a prediction the plan itself changes, and the trackers (no integrator) do not
deliver the plan exactly; that is the 09-23 fixed point (the estimate cancelled the plan's restoring
force). Instead L1 augments the closed loop it can treat as known: planner + trackers + physics, from
the ring reference r to the ring position p. Per axis (x, y, z), identified from data:

    m_eff p_dd = -k (p - r) - c p_d + sigma(t)

sigma lumps every unmodelled effect the loop cannot reject: an external force, and an internal error
(a thrust-map or mass error is a constant force mismatch). It enters through the same channel as the
reference (k r), the matched case L1 is built for.

**L1 law (piecewise constant, T_s = 0.1 s, the planner tick):**
- predictor: x_hat = [p_hat, v_hat], x_hat_dot = A_m x_hat + B (k (r + u_ad) + sigma_hat) + A_s (x_hat - x);
- adaptation: sigma_hat(k T_s) = -Phi^-1 e^(A_s T_s) (x_hat - x)(k T_s), Phi = A_s^-1 (e^(A_s T_s) - I);
- control: u_ad = -C(s) sigma_hat / k, C a first-order low-pass of bandwidth omega (the L1 filter);
- the planner flies the shifted reference r + u_ad (xy: hover point or trajectory; z: target height).

**Expected.** Static errors of either kind go to zero (C(0) = 1), with the transient bounded by the
L1 filter bandwidth rather than the adaptation rate. Wind circle: within 4 cm (like A). Twin hold:
1.048 -> 1.00 +- 1 cm with z_ki 0 (A cannot). Mass step +0.2 kg: back within 3 cm in 8 s.

**What it is not.** At steady state it acts like an integral on the reference (the supervisor's
"backdoor" objection to z_ki applies in part); the difference argued is the predictor (it separates
the response the loop explains from the part it does not, so it reacts in about one predictor time
constant) and the L1 transient bound. The critic should weigh whether that difference holds here.

## 3. The one variable

Planner knob `ring_l1` (off | on; default off, passed only when set). Parameters: identified
k, c, m_eff per axis; predictor gain A_s; filter bandwidth omega; bound on u_ad (xy 0.3 m, z 0.15 m).
Gated like option A (airborne ring in the planner phase, not landing; frozen otherwise, zeroed with
the ring down, reset on a resize; refused with z_ki > 0 and in network mode). Logs `ring_l1.csv`.
Everything else pinned to the arm's baseline config.

## Critic

**Critic, 3 Oct 2026: NOT READY.** Rewrite the card: no arm can tell C from z_ki or option A, and an
offline replay with no flights can test its matched second-order model first.

**What it is.** With a piecewise-constant law on an LTI predictor and a linear C(s), C is one fixed
linear controller: a disturbance observer on the identified loop with integral action, applied
through the reference. At steady state it is ZBias in z (R0557/R0558, SIL R0488; on the rig ZBias
railed and the ring swung 0.29-0.86 m, lift f11) plus a common-mode xy integral, which
docs/design/velocity_loop.md section 11.2 rejected because it charges on the lag while the ring tracks
a sweep. The external-force half is option A (R0864 17.9 -> R0866/R0867 3.7/3.9 cm). The predictor does
not answer the supervisor's objection (about the steady state, not the speed). Published critiques of
L1 make the "it is a linear controller" point (Ioannou et al. TAC 2014; Ortega & Panteley 2014; check
before citing).

**The +4.8 cm has a measured cause.** The force replay reads the twin hold as -1.60 N ring / +0.56 N
per drone, zeroed by the rod model (M-dist-split, M-dist-split-rod): the planner books the 0.075 kg
rod on the drone, and the twin holds 4 deg steeper than planned. C would cover that, not fix it.

**The r -> p loop is not one fixed second-order LTI plant.** A reference change is planned with
velocity, acceleration and g_eff feedforward over the 2 s horizon; a force is answered only through
the re-pinned node 0 and the trackers' P-only stiffness: same steady gain, different dynamics. The
card fits force steps and drives the predictor with r, never measuring the channel it acts through.
On orbits, fast adaptation forces the reference response down to the push dynamics; residual ratio
about 0.24 at R0832's 0.25 rad/s, i.e. about 12 cm of self-made error against R0832's 3.2 cm
(figure-8 worse). Lateral stiffness depends on rod elevation (R0860), so z couples into xy; the
vertical channel is asymmetric (t_min, CABLE_SLEW, B2 cap, throttle_max); k and m_eff change with n;
failed solves freeze the references. Upward shifts through target_z reopen the eased lift ramp and
stop traj_t; the shift must enter like z_bias.

**Matched uncertainty** holds at steady state for a ring force only, not for drone forces, a per-drone
map error, or the r -> p fit error itself (input-dependent: the L1 bound needs ||G||_L1 L < 1 with a
stated L). No A_s, omega or L given, T_s fixed by the tick: the transient-bound claim has no numbers.
Bandwidth only helps if omega is at or above the loop's own mode (~1.5 rad/s), where the fit is
weakest, the tick and solve cost 10-20 deg of phase, and the rig's 0.17 Hz heave lives; below it C is
ZBias with more parameters. The one-tick piecewise-constant estimate is a differentiated 10 Hz ring
velocity: state the u_ad jitter.

**Interactions.** With A on, both integrate the same step, and A changes the loop C was identified
on. kt_trim on: a second adaptive loop on the same vertical residual. The "gated like A" window opens
during the lift ramp and the 2 s cap release (f11's wind-up). Approach and reconfiguration holds
freeze traj_t with the ring off its reference: C would integrate that and the attach datum shift would
add it again. LAND: hold u_ad from the first descending tick (an active C would stop the descending
reference: R0852). A reset on a resize is a reference step of up to 0.3 m / 0.15 m: hold it.

**Arms.** Every "supports" bar is already met by z_ki 0.4 or A; the wind-circle fail line (8 cm) is
twice A's 3.9; the arm most likely to fail (an undisturbed orbit) is missing; the one C-only case (a
single drone's map offset) is missing.

**Locked decisions.** decisions.md:72 (the rig integral is a 0.15 m safety net, the model judged with
it off) and :93 (observer only, no new integral); C would replace the rig's safety net.
